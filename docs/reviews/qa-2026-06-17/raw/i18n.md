# i18n Audit — PDFturbo (2026-06-17)

Read-only audit of `locales/{en,fr,ar}.json` (488 flattened keys each) + `src/**/*.ts` for
un-routed user-visible strings. No source edited.

## Headline

- **Key parity: PERFECT.** en=488, fr=488, ar=488. Zero keys missing in any direction
  (verified by flattened set-diff in both directions for all three pairs).
- **No empty / TODO / FIXME / placeholder-token values** in any locale.
- **Arabic is genuinely, natively translated** — every prose value carries Arabic script; the
  only Latin-only AR values are brand/technical tokens (see below), which is correct.
- **i18n routing discipline is strong**: no literal prose reaches `showToast`, `report`,
  `alert`, `setAttribute`, `innerHTML`, `index.html` attributes, or DOM text/title/placeholder
  except decorative glyphs and one dead-data field. The i18n attribute helper (`i18n.ts`)
  drives `textContent`/`title`/`placeholder`/`alt` from `data-i18n*` attributes via `t()`.

## Negative results (checked, clean)

- `showToast` / `report` / `alert` / `confirm` — **no** call site passes a string literal; all
  args are `t(...)` results (confirmed: `showToast` is only defined, never invoked with a literal).
- `setAttribute('title'|'aria-label'|'placeholder'|'alt', …)` — only one hit
  (`progressManager.ts:61`, sets `aria-label` to `''` — intentional clear).
- `.innerHTML = literal` — all 5 hits are `= ''` (clearing), no prose.
- `.alt =` — both route through `t()` (`i18n.ts:38`, `pageThumbnailPanel.ts:207`).
- `index.html` — no `aria-label`/`title`/`placeholder` attribute lacks `data-i18n*`.
- `formFieldOverlay.ts:121` placeholder = `field.alternativeText` — that's the source PDF's own
  field content (document data), correctly not translated.
- Object-literal `label:` values (`codeGenerator.ts`, `documentModel.ts`) are barcode format
  names (EAN-13, Code 128…) and paper sizes (A4, Letter) — proper nouns, untranslatable.
